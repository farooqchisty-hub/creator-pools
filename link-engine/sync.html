Link Engine: Overview and data sync

How the dashboard stays current, what the Overview measures, and the filters and sorting on every screen.

Brevo Link Engine · built and live 26 Sep 2026 · open the Overview · build plan

The dashboard reads the database live on every request. What goes stale is how often the database hears from the outside world: Instantly (replies, sends, bounces), the link checker and discovery. So the sync plan tiers each source by how fast it actually changes, records every run, and shows the age of each source on the page.

Safety built into the schedule

  • One trigger for fast and heavy. The 5-minute cron decides which tier to run from the minute, so the two tiers never run the same step at once.
  • Dispatch lease. Dispatch holds a 4-minute lease in the database. A slow cycle still sending when the next tick fires cannot send the same reply twice. Expired leases are taken over.
  • Sync now never sends. The dashboard button pulls from Instantly and reads new replies; sending stays on the Worker's schedule and inside the Mon to Fri, 09:00 to 17:00 Detroit window.
  • Bounces close threads. Instantly status -1 closes the thread as bounced, unverifies the contact and cancels queued follow-ups; -2 suppresses the domain. The first run found paul@ecommerce-gold.com had bounced on 24 Sep with a follow-up booked for Monday.

2. Freshness, visible

Every step writes sync_state: last run, last success, last error, run counts. The Overview's freshness strip shows each source's age against its own threshold (green, amber, red): replies, sends and dispatch 15 min; bounces and Instantly stats 30 min; drafting and schedule 60 min; KPI snapshot and link checks 120 min; discovery 8 days.

The page polls /api/sync/status every 20 seconds. That returns a data version built from a handful of MAX and COUNT lookups; the Overview, Today, Won and Activity redraw only when it moves. The Overview itself is cached in KV keyed by that version (2 minute ceiling), so polling does not re-read the database.
